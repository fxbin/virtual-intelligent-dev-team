Why Closure Layer

为什么需要闭环协调层

单点专家解决的是"换一个视角"，闭环协调层解决的是"如何把多视角收敛成可交付、可回滚、可验证的结果"。

01

单专家不够

跨域任务找不到唯一负责角色，前端、后端、安全、产品、发布各有立场，但缺少一个负责"谁主、谁辅、是否需要治理"的协调层。

02

单轮回答不够

复杂任务需要"计划 → 执行 → 验证 → 迭代"的闭环，而不是一次性建议。缺少基线、轮次记忆与回滚点的工作流很容易越改越乱。

03

路由不可见

决策黑箱，无法审计和回滚。一旦结果不对，难以追溯是哪个路由判断、哪一轮迭代、哪一次 fallback 引入的偏差。

Six Closures + Delivery Subgraph

六层闭环与交付子图

每一层都有触发条件、核心机制与关键产物；只在任务确实需要时激活，不做无意义流程升级。

L1
Planning
大改写先规划：迁移、重构、项目级改造前置一份轻量 Planning Pack 与进度锚点。
L2
Routing
按 task shape 路由：依据风险、技术栈、Git 与流程信号选择 lead、assistant、governance 轨道。
L3
Delivery
快切片交付：窄实现与 bugfix 保留 brief、项目上下文、delivery status 与完成证据。
L4
Iteration
有界优化循环：保留 baseline、round memory、self-feedback 与 keep / retry / rollback / stop。
L5
Release
ship / hold 门禁：release gate 不只看 benchmark 绿，还要求结构化完成证据。
L6
Drill
离线演练：验证回滚、resume、release-gate bootstrap 路径是否真的跑得通。
D1
Delivery Subgraph
Team Engine Lite 内嵌于 Delivery：Verifier 支持 pass / fail / hold / spec_violation，Lead 仅在 DeliveryCycleReport 后接受。

Quick Start

三种调用方式

默认手动模式适合高风险任务；显式 /auto 进入两阶段自动运行；单专家路由用于领域清晰的小切片。

Manual Mode

手动模式

不带 /auto，逐轮确认路由与执行路径，适合高风险任务和需要人工把关的发布决策。 

# 接管重构并给出可执行分工
$virtual-intelligent-dev-team 帮我接管这次
重构，并给出可执行分工。
/auto Mode

/auto 自动运行

显式 /auto 进入 setup → go 两阶段协议，先建 automation state，再执行有界迭代。 

# 项目级迁移：先建状态再执行
$virtual-intelligent-dev-team
/auto setup 这个项目级迁移。
$virtual-intelligent-dev-team
/auto go
Expert Routing

单专家路由

领域清晰的小切片直接路由到对应专家，保留 quick slice brief 与完成证据。 

# 邮箱验证小切片：路由到 Technical Trinity
$virtual-intelligent-dev-team
实现用户登录功能的邮箱验证

开始你的第一个闭环任务

从一个简单的小切片开始，让协调层接管路由、验证与回滚，把"再来一轮"变成可追溯的迭代。
