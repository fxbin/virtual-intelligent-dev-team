Smallest sufficient route

不同任务，走不同重量的路线。

系统优先选“足够完成任务的最小流程”，只有风险、规模或证据要求上升时才增加协作与门禁。

Quick slice

小功能与 Bugfix

单 Lead、小范围实现、针对性验证与简洁 evidence。不会自动召集完整团队。

  • 推荐：direct-execution
  • 保留 Quick Slice Brief
  • 失败时再升级
Plan first

重构、迁移与高风险变更

先拆阶段与回滚点，再进入实现；Sentinel Architect 对边界和治理负责。

  • 推荐：plan-first-build
  • 显式 non-goals
  • 阶段性恢复锚点
Product council

PRD、原型与产品定义

由 World-Class Product Architect 负责，可按需展开产品发现或原型设计专家团。

  • 推荐：product-spec-deliver
  • Stage Council 仅为 overlay
  • 验收与研发路径同源
Specialist roster

八个专家，不是八个人同时说话。

每次任务有唯一 Lead。协作角色只在边界明确、产物可交接时进入，避免角色数量掩盖责任缺口。

直接调用 skill 不需要额外安装。只有运行仓库里的维护、路由、schema 或 benchmark 脚本时，才需要安装 Python 依赖。

/virtual-intelligent-dev-team 实现用户登录功能的邮箱验证
  1. 说目标，不用先选 Agent

    系统会判断 Lead、风险、workflow 和是否需要意图确认。

  2. 检查范围与验收

    复杂任务会先锁定 GoalFrame；小任务保留轻量 Quick Slice Brief。

  3. 根据证据决定完成

    测试、产物和残余风险进入 completion evidence；“看起来可以”不是发布依据。
