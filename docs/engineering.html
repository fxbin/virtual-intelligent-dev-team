Engineering Pillars

让 LLM 在真实软件工程里更可靠的四根工程化支柱

路由与七层闭环解决的是"谁来做、怎么收口"，但这不够。真实软件工程里 LLM 的痛点是：实现前不约束、自产自审、旧路径永不退休、永远"再来一轮"。这四根支柱就是针对这四个痛点设计的工程化门禁，也是本项目区别于"换几个角色回答"的核心差异化所在。

P1

Harness 工程约束门禁

Engineering Constraint Gate
6 个 code-facing bundle

6 个 code-facing bundle（plan-first-build / product-spec-deliver / audit-fix-deliver / govern-change-safely / root-cause-remediate / direct-execution）执行前必须先创建或刷新 .skill-harness/engineering-constraints.md，把"实现前先约束"从建议变成硬门禁。Agent 可以先看代码，但在工程约束明确之前不能开始改生产文件。

必填章节
  • Scope
  • Non-Negotiable Constraints
  • Forbidden Changes
  • Verification Evidence
  • Rollback And Stop Conditions
P2

Team Engine Lite 对抗式验收

Worker / Verifier / Lead Separation
11 状态机 · 5 标准对象

Worker 只产不验、Verifier 只验不产、Lead 只能基于 DeliveryCycleReport 接受。配合 3 级 runtime claim（real_subagent_runtime / single_backend_multi_session / soft_orchestration_only），禁止把角色扮演误称为真实多 Agent runtime。没有宿主 spawn / wait / merge 证据时，声明始终保持 soft_orchestration_only。

标准对象
  • WorkOrder
  • ImplementationOutput
  • VerificationReport
  • RemediationPatch
  • DeliveryCycleReport
P3

Anti-Entropy 反熵治理

Anti-Entropy Governance
delete-first / compat-exception / confirmation-first

遇到 duplicate owner、fallback、adapter、guard 或兼容路径增长时，先按目标分类（code-retirement / contract-carrying-code / derived-state / persistent-state），再选路径：delete-first（能删就删）、compat-exception（保留兼容但登记例外）、confirmation-first（未知依赖先问人）。核心原则：未知依赖不等于活跃依赖证据。

触发信号
  • duplicate owner
  • fallback growth
  • adapter / guard 膨胀
  • delete vs compat 边界
  • source-of-truth 删除边界
P4

Self-Optimization 自优化循环

Bounded Iteration + Mutation Catalog
live ≤3 · offline ≤120 · same-hypothesis ≤2

可对自身的 routing-rules.json / regression-cases.json / evals.json 做 JSON-aware 确定性自优化。Live 模式最多 3 轮、Offline 模式最多 120 轮、同一假设最多 2 次重试。所有 rollback / keep / pivot / resume / hold→bootstrap→auto-run 路径都可以通过 offline loop drill 离线验证，不让自优化变成"无限自转"。

Mutation 操作族
  • json_set
  • json_merge
  • json_delete
  • append_unique
  • regex_replace
