Harness gate

在实现开始前，把不可妥协项写进文件。

六个 code-facing bundle 必须先创建 .vidt/harness/engineering-constraints.md。这是执行门禁，不是事后说明。

Scope
清楚列出 in scope 与 out of scope，防止“顺手重构”扩大改动面。
Non-Negotiable Constraints
记录必须守住的版本、协议、安全、兼容性、依赖与环境边界。
Forbidden Changes
显式写出不能改什么，尤其是用户数据、无关模块和未经授权的外部状态。
Verification Evidence
在编码前就决定什么命令、测试、截图或 artifact 能证明完成。
Rollback And Stop Conditions
声明何时回滚、何时停止尝试、何时升级给人工决策。
轻量不等于省略

小切片可以用短约束，但不能把关键边界只留在对话记忆里。

Anti-entropy

“未知依赖”不是保留旧代码的充分理由。

先识别旧对象承载什么，再选择 delete-first、compat-exception 或 confirmation-first；所有权不清时才升级人工确认。

Classify

四类对象

  • code-retirement：退出的代码路径
  • contract-carrying-code：仍承载外部契约
  • derived-state：可重建的派生资产
  • persistent-state：用户或系统持久数据
Decide

三条路径

  • delete-first：无活跃契约与数据风险，直接退役
  • compat-exception：有证据证明仍需兼容，明确期限与 owner
  • confirmation-first：涉及持久数据、外部权限或不可逆边界
  1. 建立调用方证据

    搜索代码、文档、workflow、消费者与真实运行状态，不靠猜测保留旧路径。

  2. 声明新 canonical owner

    删除旧路径前说明行为迁往何处，避免形成双真源。

  3. 同步引用与回归覆盖

    删除、重命名或迁移必须在同一轮修复所有指针和验证门禁。

  4. 禁止永久兼容层

    若确需兼容，必须记录期限、责任人、退出条件和持续测试成本。

Evidence gate

完成证据必须能被另一个人重放。

非平凡完成声明包含 action、result、covered scope、uncovered scope、residual risk、confidence grade 和 evidence refs。

repository gates

python scripts/lint_virtual_team_contract.py
python -m unittest discover -s tests -p 'test_*.py'
python scripts/check_harness_health.py --skill-dir .

证据的最低标准

  • 命令与目标文件、模块或行为直接相关
  • 结果含退出码、状态或可检查 artifact
  • 明确哪些范围未测、为何未测
  • 残余风险与置信等级不被“全绿”隐藏
  • release gate 可读取同一份结构化 evidence
Benchmark 不是完成声明

Benchmark 证明某类行为基线，不自动证明当前实现、Git 状态、部署边界或用户路径已经完成。
