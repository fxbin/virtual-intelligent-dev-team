为什么需要闭环协调层？

普通多专家提示词在复杂软件任务中有三个结构性缺口

01
角色堆砌 ≠ 协同
平铺多个角色视角，没有判断谁主负责、谁协同、是否需要治理。复杂任务里"谁来 lead"比"有几个专家"更重要。
02
单轮回答 ≠ 闭环
只给建议，没有执行路径、恢复锚点和下一步。真实软件交付需要跨多轮、跨多天、可恢复的状态管理。
03
发布前判断 ≠ 全链路
只覆盖"能不能发"，缺少 beta、release gate、completion evidence、post-release feedback 的连续治理链路。

3 种调用方式

默认手动模式，显式 /auto 才进入自动运行

① 手动模式
$virtual-intelligent-dev-team 帮我评估这次
重构的最佳负责人
和执行顺序。
高风险任务逐轮确认，输出 lead route + workflow bundle + resume anchor
② /auto setup
$virtual-intelligent-dev-team /auto setup
这个项目级迁移。
建立 automation state + 恢复锚点，为后续 go 或 resume 准备状态
③ /auto go
$virtual-intelligent-dev-team /auto go → 进入自动执行
有边界执行 + 状态优先恢复 + 保留 resume 锚点
设计原则：自动化能力越强，越不能默认打开。默认 manual，只有显式 /auto 才进入自动运行，保持 setup → go 两阶段协议。
