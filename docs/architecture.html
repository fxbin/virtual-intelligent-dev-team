Architecture · v6.0.19

六层闭环，一条证据链。

系统架构围绕“责任如何传递、证据如何累积、失败如何停止”组织。顶层是六层持续闭环；Delivery 内部是 Team Engine Lite；专家团只是阶段 overlay。

System map

外层管生命周期，内层管一次交付。

六层 Closure 不等于六个 Agent。它们是任务从意图到反馈的连续责任区；角色和工作流按每一层的目标进入。

Closure layers

每一层都有明确的进入条件和退出证据。

闭环避免把规划、实现、内测、发布混成一轮输出，也避免任务在对话结束后失去恢复位置。

01 / Intent & Routing

先决定“该做什么、谁负责”

对低信息量想法先做意图确认；对明确任务选择唯一 Lead、最小 workflow bundle 和必要协作。

  • 输出 RouteDecision
  • 拒绝无边界的角色堆叠
  • 不确定时保持 provisional route
02 / Planning

先定义完成，再开始执行

复杂目标锁定 success evidence、stop condition、non-goals、阶段和恢复锚点；小任务使用 Quick Slice Brief。

  • 输出 GoalFrame / Planning Pack
  • 显式风险与回滚
  • 宽目标先收敛
03 / Delivery

分离生产与验收责任

Lead 发出 WorkOrder，Worker 产出 ImplementationOutput，Verifier 给出独立报告，Engine 决定接受、重试或升级。

  • 有限 max cycles
  • 失败必须带 RemediationPatch
  • 证据不足进入 hold
04 / Beta

用分轮学习替代主观感觉

定义 cohort、轮次目标、反馈门禁和退出条件。模拟用户只能作为验证工具，不能冒充真实用户证据。

  • 输出 Beta Manifest
  • 分离发现与修复轮次
  • 保留 uncovered scope
05 / Release

让 ship / hold 成为证据决策

发布门禁检查版本、测试、变更范围、回滚、状态和 completion evidence；只有 benchmark 绿色仍不够。

  • 输出 ReleaseDecision
  • Git 操作遵守权限边界
  • 残余风险必须显式
06 / Feedback

把上线结果接回下一轮

监控信号、用户反馈和指标漂移进入下一轮目标，不用“已发布”替代生命周期完成。

  • 输出 NextIteration
  • 状态优先恢复
  • 停止条件继续生效
Team Engine Lite

Delivery closure 的对抗式交付子图。

它只在 code-facing、release-facing、Git-facing 或 remediation 任务中承担交付协议，不取代六层闭环，也不把角色扮演称为真实并行。

查看门禁与证据对象 →
  1. Lead → WorkOrder

    定义目标、输入、范围、验收、禁止项、证据命令和超时边界。

  2. Worker → ImplementationOutput

    只负责产出与自述，不拥有最终通过权。

  3. Verifier → VerificationReport

    按 WorkOrder 和客观规范独立验证，给出 pass / fail / hold / spec_violation。

  4. Engine → Transition

    根据状态机进入 accepted、retrying、escalated 或人工决策，不无限循环。

  5. Lead → DeliveryCycleReport

    只基于完整周期报告接受结果，并把覆盖面和残余风险带入后续 Closure。

Runtime claims

三档运行方式，能力缺口会自动降级。

请求资格与宿主能力链必须同时满足。缺少 spawn / wait / merge 或 session 生命周期能力时，系统 fail closed 到更低层级。

Tier 1

real_subagent_runtime

宿主提供完整真实 subagent 能力链，角色能独立运行、等待、合并并留下 runtime evidence。

Tier 2

single_backend_multi_session

同一后端创建多个受控 session，生命周期能力必须完整，不能把普通文本分工冒充多进程。

Tier 3

soft_orchestration_only

默认安全层级：只声明角色、顺序、文件交接与证据边界，不声称真实并行 Agent runtime。

14-state machine

accepted 只能由 passed 或人工确认后的 resumed 进入；规范违例不能被普通重试静默覆盖。
